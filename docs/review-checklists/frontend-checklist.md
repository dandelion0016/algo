# フロントエンド レビュー観点チェックリスト (frontend-checklist.md)

本チェックリストは、フロントエンドUI/UX実装およびPRレビュー時に検証すべき品質・受入観点を定義します。
画面チェック項目の漏れによるUI不具合（スクロール見切れ、ボタン押下不能、黒バー露出等）の再発を防止するため、以下の観点を厳格に点検します。

---

## 1. モバイル・ビューポート ＆ スクロール完全性（Issue #103 再発防止）
- [ ] **オーバースクロール・ラバーバンドバウンス制御**:
  - `html, body` に `overscroll-behavior-y: none;` が指定され、iOS Safari や Android Chrome でのスワイプ時に不要なラバーバンドバウンスが発生しないこと。
- [ ] **下地色・テーマカラーとボディ背景色の一致**:
  - `layout.tsx` の `body` クラス（`bg-algo-sand text-slate-800` 等）と CSS 変数 `--background`、Next.js `Viewport` の `themeColor`（`#fafaf7`）が完全に整合していること。
  - 万一オーバースクロールや隙間が発生しても、下地の黒（`bg-zinc-950` 等）が「黒いバー」として露出・視認されないこと。
- [ ] **ビューポート高さ指定の整合と縦超過（100dvh二重指定）の禁止**:
  - 親コンテナと子コンテナの双方に `h-[100dvh]` を安易に指定してフッターや子要素を押し出す「100dvh二重指定」を禁止。
  - 親コンテナを `h-[100dvh] max-h-[100dvh] flex flex-col` とし、メインコンテンツを `flex-1 min-h-0` で伸縮させることで、フッターとの合計が画面高（100dvh）にジャストフィットすること。
- [ ] **Safe Area Inset (ノッチ・ホームインジケーター) への配慮**:
  - 画面最下部（フッター、固定バー、手札エリア）に `pb-[max(0.25rem,env(safe-area-inset-bottom))]` 等の Safe Area Inset が適切に付与され、iPhone 等のホームバーとUIが重ならないこと。
  - Next.js `Viewport` に `viewportFit: 'cover'` が設定されていること。

---

## 2. 小画面端末での操作ボタン到達性・非クリッピング保証（Issue #110 再発防止）
- [ ] **最重要アクションボタンの非クリッピング（物理切り落としの根絶）**:
  - モバイル（`lg` 未満）において、親またはラッパーに安易な `overflow-hidden` を適用して重要ボタン（「対戦を開始する！」「山札から引く」「アタックする」「ステイする」）を物理的に切り落とさないこと。
  - 必ず `overflow-y-auto overscroll-contain` 等のスクロール安全網（Safety Net）を確保し、どの端末でも最下部ボタンまで確実にスクロール到達・タップ可能であること。
- [ ] **小画面（iPhone SE 375x667等）でのスクロールフリー・最適配置**:
  - 高さが極小のスマートフォン（高さ 667px 以下）でも、無駄な上下余白・パディング・ヘッダー高さを圧縮し、通常の手番操作（ドロー・ターゲット選択・手札閲覧）が可能な限りスクロール不要で1画面内にスッキリ収まること。
  - モーダル（セットアップ画面、ルール画面、結果画面等）は `max-h-full flex flex-col` とし、内部フォームに `overflow-y-auto` を設定して「開始ボタン」が常時アクセス可能であること。
- [ ] **4人対戦など最大情報量表示時におけるレスポンシブ破綻防止**:
  - 対戦相手が最大人数（4人対戦・相手3体）の際、相手手札エリアが縦に肥大化して中央アクションボタンやプレイヤー手札を画面外へ押し出さないこと。
  - 相手エリアの横スクロール（カルーセル/スライド）またはコンパクトグリッド配置により、情報密度が高まってもレイアウト崩れを起こさないこと。

---

## 3. レスポンシブ・マルチデバイス表示検証
- [ ] **全ブレークポイントでのメタ情報視認性**:
  - スマートフォン（幅 < 640px）、タブレット（640px 〜 1023px）、デスクトップ（>= 1024px）の全解像度において、バージョン表記（`getAppVersion()`）やシステムメタ情報が不意に `hidden lg:block` 等で非表示・見切れになっていないこと。
  - モバイルの縦長画面（高さ 600px〜850px）でモーダルやフッターがスクロールバーや他要素と重複していないこと。
- [ ] **タッチ・キーボード操作性**:
  - 2桁数字入力（10, 11）や物理キーボード操作、モバイルソフトウェアキーボード表示時のレイアウト崩れがないこと。
  - タップターゲットが適切なサイズ（最小 36px〜44px 以上）を確保し、押し間違えを防ぐ余白が確保されていること。

---

## 4. バージョン埋め込み・クライアントバンドル整合性
- [ ] **環境変数の静的置換**:
  - クライアントコンポーネントにおける `NEXT_PUBLIC_APP_VERSION` の参照が正しくビルド時インライン展開されること。
  - 未注入時・ローカル開発時でも異常停止せず、意図通りの表記が得られること。

---

## 5. 自動テスト完全性 ＆ E2E（品質保証基準の強化）
- [ ] **モバイルViewportでのPlaywright E2E検証**:
  - モバイル解像度（375x667, 390x844）でE2Eテストを実行し、以下の各ボタンが `toBeVisible()` かつタップ可能（クリッカブル）であることを機械的に保証すること：
    - セットアップ画面の「対戦を開始する！」ボタン
    - 2人〜4人対戦時の「山札を引く（ドロー）」ボタン
    - 相手伏せカード選択およびアタック確認ボタン
    - プレイヤー手札カード
- [ ] **ビューポート内可視性アサーション（`toBeInViewport()`）の積極活用**:
  - 最重要アクションボタンが画面外に見切れていないか、`expect(locator).toBeInViewport()` 等を活用してE2Eアサーションを強化すること。
- [ ] **DOMテスト完全性**:
  - `@testing-library/react` による状態遷移・ユーザーイベントテストがすべてパスしていること。
  - `npm run test:integrity`（テスト完全性監査）において改ざん・骨抜きがないこと。
