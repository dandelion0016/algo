# システム要件定義書: アルゴ（algo）Web対戦システム

## 1. プロジェクト概要

### 1.1 背景と目的
「アルゴ（algo / Coda / Da Vinci Code）」は、算数オリンピック委員会・東京大学数学科の学生有志・数学者ピーター・フランクル氏らが共同開発した、伏せられた相手の数字カードを推理する大人気頭脳派ボードゲームです。
本プロジェクトは、このアルゴの魅力をWeb上で手軽かつ本格的に体験できるWebアプリケーションを構築することを目的とします。
まずは一人でいつでも手軽に思考戦を楽しめる**「CPU対戦モード」**を最優先で実現し、将来的には離れた友人や全国のプレイヤーとリアルタイムで対戦できる**「オンライン対戦モード」**へ拡張可能な設計を採用します。

### 1.2 コアバリュー
1. **高い論理的思考体験**: ルールに忠実なカード配置・開示ルール、論理的消去法に基づいたCPU思考AI。
2. **直感的で洗練されたUI/UX**: 物理カードの質感・伏せ状態・開示アニメーションをWeb上で美麗に再現（パステルイエロー `#FCF97A` × スカイブルー `#7BA6EF` の北欧モダンテイスト）。
3. **拡張性と堅牢性**: 将来のWebSocketリアルタイムオンライン対戦・ユーザー戦績保存に耐えうるモジュール化アーキテクチャ。
4. **AWS無料枠最大活用によるゼロコスト運用**: 常時無料枠（Always Free）を最大限活かしたサーバーレス構成による運用コスト極小化。

## 2. アルゴ ゲームルール定義

### 2.1 カードコンポーネント
- **カード総数**: 全24枚
  - **黒カード (Black)**: 0 〜 11（各1枚、計12枚）
  - **白カード (White)**: 0 〜 11（各1枚、計12枚）
- **カードの公開属性**:
  - `表向き (Open)`: 数字と色が全プレイヤーに見えている状態。
  - `裏向き (Closed)`: 色（黒/白）のみ全プレイヤーに見えており、数字は所有者（自分）にのみ見えている状態（相手からは「?」）。

### 2.2 カードの並び順ルール（最重要規約）
全プレイヤーの手札は、左から右へ以下の順序関係で厳密にソートされて並ぶ：
1. **小さい数字が左、大きい数字が右**。
2. **同じ数字の場合は「黒」が左、「白」が右**（黒 < 白）。
- 順序関係: `(0, 黒) < (0, 白) < (1, 黒) < (1, 白) < ... < (11, 黒) < (11, 白)`

### 2.3 対戦人数と初期手札枚数（公式ルール準拠）
- **2人対戦**: 初期手札 **各4枚**（山札16枚）
- **3人対戦**: 初期手札 **各3枚**（山札15枚）
- **4人対戦**: 初期手札 **各2枚**（山札16枚）

### 2.4 ゲームフロー
1. **初期配置**:
   - 24枚をシャッフルし、人数に応じた初期手札を裏向きで配布しルール順に整列。残りを山札として配置。
   - プレイヤー（人間）先攻で開始。
2. **手番（ターン）の実行**:
   - **Step 1: ドロー**: 山札から1枚引く（手番プレイヤーのみ数字を確認）。※山札0枚時は直接アタックへ。
   - **Step 2: アタック（推理）**: 相手の裏向きカードを1枚選び、数字（0〜11）を予想宣言。
   - **Step 3: 判定と分岐**:
     - **【的中（正解）】**:
       - 相手の該当カードを表向き（Open）にする。
       - そのプレイヤーの全カードが表向きになった場合、そのプレイヤーは脱落。
       - 生き残りが1人になったらゲーム終了（完全勝利）。
       - 継続時: 「続けてアタック（コンティニュー）」または「ステイ（引いたカードを裏向きで手札に加え手番終了）」を選択。
     - **【ハズレ（不正解）】**:
       - 引いたカードを表向き（Open）にして自分の手札の正しい位置に加える（相手に情報開示するペナルティ）。
       - 手番は次のプレイヤーへ移行。
3. **勝敗条件**:
   - 最後まで伏せカードを1枚以上残して生き残ったプレイヤーの勝利（サバイバル戦）。

## 3. 機能要件

### 3.1 ゲーム設定（初期セットアップ画面）
- **対戦人数選択**: 2人対戦 / 3人対戦 / 4人対戦
- **CPU難易度選択**:
  - `初級 (Easy)`: 既知カード除外のみでランダム推理（気楽に遊びたい方向け）
  - `中級 (Normal)`: 左右のオープンカードによる範囲制約＋論理的推論（標準）
  - `上級 (Hard)`: 確定マス最優先・過去ログ消去法・確率最大化（本格思考戦）
- **持ち時間（ターン制限）選択**:
  - `30秒`: 標準テンポ（推奨）
  - `15秒`: 早指しスピーディ（スリリング）
  - `無制限`: じっくり長考（マイペース）
  - 制限時間内にアタックまたはステイを行わなかった場合、時間切れペナルティとして引いたカードが強制オープンされて手番終了。

### 3.2 UI/UX機能
- **カラーパレット**: パステルイエロー（`#FCF97A`）、スカイブルー（`#7BA6EF`）、サンドホワイト（`#FAF9F5`）、チャコールネイビー
- **アニメーション**: ドローアニメーション、アタック可能カードの脈動パルス、的中・ハズレ演出、タイマー警告パルス
- **対戦ログパネル**: 各ターンの推理結果（的中/ハズレ、推理数字）をリアルタイム表示
- **ルール解説モーダル**: いつでも公式ルールを確認可能
- **レスポンシブ対応**: PC・タブレット・スマートフォン完全対応

### 3.3 将来拡張（オンライン対戦機能 - Phase 2構想）
- ルーム作成・合流（Room ID / URL共有）
- WebSocket（Supabase Realtime / AWS AppSync / API Gateway WebSocket）による双方向リアルタイム同期
- チャット・リアクション機能

## 4. クラウドインフラ基盤要件 (AWS利用方針 ＆ 無料枠最大活用)

### 4.1 基本方針
- クラウドプロバイダーとして **AWS (Amazon Web Services)** を採用する。
- 個人開発・小規模運用におけるコスト最適化を最優先とし、**「AWS 常時無料枠 (Always Free)」および「12ヶ月無料枠 (12-Month Free Tier)」の枠組み内に収め、月額利用料 $0 を達成する** サーバーレス・静的アーキテクチャを策定・構築する。

### 4.2 インフラ構成および無料枠の適用設計

| レイヤー | 採用AWSサービス | 役割・用途 | AWS無料枠の適用とコスト対策 |
| :--- | :--- | :--- | :--- |
| **CDN / 配信** | **Amazon CloudFront** | グローバルエッジ配信、HTTPS終端、高速キャッシュ | **常時無料**: 毎月 1TB のデータ転送、1,000万リクエストまで $0。個人運用では十分な容量。 |
| **静的ホスティング** | **Amazon S3** | Next.js 静的エクスポート成果物 (HTML/CSS/JS/画像) の格納 | **12ヶ月無料**: 5GB ストレージ、20,000 GETリクエスト/月。以降も月額数十円未満。 |
| **API / バックエンド**<br>(将来拡張時) | **AWS Lambda** | サーバーレスビジネスロジック、対戦マッチング、戦績記録 | **常時無料**: 毎月 100万リクエスト、400,000 GB-秒のコンピュート時間が永久無料。 |
| **API Gateway**<br>(将来拡張時) | **Amazon API Gateway**<br>(HTTP API) | LambdaのREST/HTTPエンドポイント公開 | **12ヶ月無料**: 毎月 100万リクエストまで無料。低レイテンシ・低コストなHTTP APIタイプを採用。 |
| **データベース**<br>(将来拡張時) | **Amazon DynamoDB** | オンラインルーム状態、ユーザープロファイル、対戦履歴の永続化 | **常時無料**: 25GB ストレージ、25 WCU / 25 RCU（毎月約2億リクエスト分）が永久無料。 |
| **認証基盤**<br>(将来拡張時) | **Amazon Cognito** | ユーザー登録・ソーシャルログイン・JWT発行 | **常時無料**: 月間アクティブユーザー (MAU) 50,000人まで永久無料。 |
| **セキュリティ・認可** | **AWS IAM** | 最小権限の原則に基づくサービス間ロール、デプロイ用ロール | 完全無料。ワイルドカード特権（`*`）を禁止し、必要最小限の権限のみ付与。 |
| **CI/CD パイプライン** | **GitHub Actions + AWS OIDC** | 自動テスト、ビルド、S3/CloudFrontへの自動デプロイ | **AWS OIDC認証** を採用し、長期アクセスキーを発行せず一時認証情報で安全に実行（完全無料）。 |

### 4.3 ゼロ課金ガード（課金暴走防止機構）
1. **AWS Budgets アラーム設定**:
   - 月額の予想利用料金が **$0.01（1セント）** を超えた時点で、管理者のメールアドレスへ即座に通知する予算アラートを設定。
   - 無料枠超過や予期せぬアクセス集中による課金を即座に検知・対処可能とする。
2. **CloudFront 自動リクエストレート制限 (AWS WAF 検討 / 制限)**:
   - 悪意あるDDoSやクローラーによる大量リクエストを抑止し、無料枠内での安全な運用を担保。
