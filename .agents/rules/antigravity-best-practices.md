# Antigravity 開発ベストプラクティス

公式リファレンス: [Best practices for Antigravity CLI / IDE](https://antigravity.google/docs/cli/best-practices/)

エージェントおよびサブエージェントは、高い開発速度とコード品質を維持するために以下のベストプラクティスを徹底すること。

## 1. 検証ループ（Verification Loops）の義務化
- **Test-First（テスト先行）の原則**:
  - 実装を開始する前に、既存テストスイートの有無を確認する。テストが存在しない場合は、まず標準的なテストコードの雛形を起案すること。
- **自律的検証と自己修正（Iterate on test outputs）**:
  - コード変更を行った後は、必ずローカルのテストコマンド（`npm test`, `pytest`, `cargo test` 等）またはビルドコマンドを実行し、自律的に結果を検証すること。
  - テスト失敗やビルドエラーが発生した場合は、人間に助けを求める前に、エラーログを分析して自律的に修正ループを回すこと（最大3〜5回の反復）。

## 2. 探索 → 計画 → 実行（Explore, Plan, then Execute）
- **いきなりコードを書かない**:
  1. **Explore（探索）**: 対象コードベースのルーティング、インターフェース定義、既存のデータフローを探索・理解する。
  2. **Plan（計画）**: 変更対象ファイル、追加依存関係、設計のトレードオフを Implementation Plan として出力し、承認を得る。
  3. **Execute（実行）**: 計画の合意後にのみ、最小限の差分でコード変更を適用する。

## 3. コンテキストエンジニアリングとプロンプト最適化
- **ファイルパスの明示（Target file autocompletion）**:
  - ファイル参照には常に `@パス` 記法を用い、エージェントのコード探索範囲を絞り込んでトークン消費とノイズを抑える。
- **視覚的エビデンス（Visual Evidence）の活用**:
  - フロントエンドのレイアウト崩れやUIバグの検証時は、スクリーンショットやブラウザ録画アーティファクトを参照・添付して診断する。

## 4. サンドボックスと安全な権限管理
- **Terminal Sandbox の活用**:
  - ターミナルコマンドはサンドボックス（`proceed-in-sandbox`）内で実行し、安全なローカル検証コマンドは自律実行させつつ、外部破壊リスクを隔離する。
- **Git・外部通信の防護**:
  - `git push` や外部へのデプロイ・パブリッシュ操作は、必ず人間の明示的承認（`ask`）を経て実行する。

## 5. 仕様の永続化（Spec-Driven Development）
- **仕様をチャット履歴に埋もれさせない**:
  - 検討した仕様やアーキテクチャ設計は、必ず `specs/<feature>/spec.md` にMarkdownファイルとしてコミット・永続化し、Gitでバージョン管理する。
- **単一の真実源（Single Source of Truth）**:
  - 実装中やレビュー中に疑問が生じた場合は、常に `spec.md` を立ち戻るべき真実源として参照する。

## 6. 並列サブエージェント（Parallel Subagents）の活用
- **Fan-out（並列展開）**:
  - 複数モジュールにまたがる調査や独立したタスクは、管理者がバックグラウンドの並列サブエージェントに切り離して委託し、メインセッションのコンテキスト肥大化を防ぐ。
